> Open-source flight tracker у стилі Flightradar24.
> Ціль: pet-проєкт рівня Senior/Tech Lead для портфоліо + реально користна штука.
> Бюджет: **0 €**. Обладнання: **нуль додаткового заліза** — тільки публічні API.

## 0. Summary для агента

Ти будуєш повнофункціональний веб-трекер літаків: жива карта з десятками тисяч
бортів у реальному часі, деталі рейсу, історія треків, фільтри, статистика,
сторінки аеропортів і бортів.

Читай цей файл повністю перед першим комітом. Правила автономії, дозволи
і стиль роботи — у `CLAUDE.md` поруч.

**Ключові інваріанти, які не можна порушувати:**

1. Жодних платних сервісів, жодних кредитних карток, жодного заліза.
2. Жодного скрейпінгу приватних API Flightradar24 / FlightAware / RadarBox.
   Тільки офіційні публічні ендпоїнти community-мереж.
3. Дані ODbL → атрибуція обов'язкова у футері та в `ATTRIBUTION.md`.
4. Проєкт некомерційний. У README це має бути написано явно.
5. Рендер карти — тільки WebGL. Жодного DOM-маркера на літак.

## 1. Джерела даних

### 1.1 Основне: adsb.lol

Повністю відкритий community-трекер. Дані під ODbL, безкоштовний API без
реєстрації, є історичні дампи.

```
Base: https://api.adsb.lol/v2

GET /lat/{lat}/lon/{lon}/dist/{nm}   # борти в радіусі, nm ≤ 250
GET /hex/{icao24}                     # один борт за ICAO hex
GET /callsign/{callsign}
GET /squawk/{squawk}                  # 7500/7600/7700 — emergency
GET /mil                              # військові борти
GET /ladd                             # LADD-блоковані (FR24 їх ховає, ми — ні)
GET /pia                              # Privacy ICAO Address
```

Відповідь: `{ ac: [...], total, now, ctime, ptime }`.
Ключові поля об'єкта борту:

| поле | значення |
|---|---|
| `hex` | ICAO24 hex, унікальний ID борту |
| `flight` | callsign (може бути з пробілами в кінці — тримай) |
| `r` | реєстрація (напр. `CS-TJF`) |
| `t` | тип ICAO (напр. `A20N`) |
| `lat`, `lon` | позиція |
| `alt_baro` | барометрична висота, фути; може бути рядок `"ground"` |
| `alt_geom` | геометрична висота |
| `gs` | ground speed, knots |
| `track` | курс над землею, градуси |
| `baro_rate` | вертикальна швидкість, ft/min |
| `squawk` | транспондер-код |
| `emergency` | `none` / `general` / `lifeguard` / `minfuel` / `nordo` / `unlawful` / `downed` / `reserved` |
| `category` | A0–C7, вагова категорія |
| `nav_altitude_mcp` | висота виставлена в автопілоті — цінна штука |
| `seen` | секунд тому бачили останній пакет |
| `seen_pos` | секунд тому була остання позиція |
| `messages` | скільки пакетів прийнято |
| `rssi` | сила сигналу |
| `mlat`, `tisb` | масиви полів, отриманих не з ADS-B |

### 1.2 Дзеркала / фолбеки (той самий формат)

- `https://api.airplanes.live/v2/...` — той самий контракт
- `https://opendata.adsb.fi/api/v2/...` — той самий контракт
- `https://api.adsb.one/v2/...`

Реалізуй **провайдер-абстракцію** з фейловером по колу і health-check'ом.
Якщо провайдер дає 429/5xx тричі поспіль — тимчасово виключай його на 60 с.

### 1.3 OpenSky Network (вторинне, для покриття)

Безкоштовний для дослідницького/особистого використання, є REST і історія
для зареєстрованих. Мінуси: жорсткі rate-ліміти, немає гарантій аптайму,
некомерційна ліцензія.

```
GET https://opensky-network.org/api/states/all?lamin=&lomin=&lamax=&lomax=
```

Використовуй **тільки** як фолбек для регіонів з поганим покриттям community-мереж.
Ліміт анонімно — низький; кешуй агресивно (мін. 10 с TTL).

### 1.4 Статичні датасети (завантажити один раз, покласти в репо/S3-подібне)

| що | звідки | розмір |
|---|---|---|
| Аеропорти світу (~78k) | OurAirports CSV (public domain) | ~10 МБ |
| Авіакомпанії, ICAO/IATA коди | OpenFlights (ODbL) | ~1 МБ |
| Типи ПС, ICAO designators | Вікідані / mictronics db | ~500 КБ |
| Реєстрації → оператор | mictronics `basic-ac-db` | ~40 МБ |
| Країна за ICAO24-префіксом | таблиця ICAO Annex 10 | вручну, ~300 рядків |

Пиши скрипт `scripts/fetch-static-data.ts`, який тягне все це, нормалізує
в компактний бінарний/parquet формат і кладе у `data/`. Скрипт має бути
ідемпотентним і запускатися через `npm run data:refresh`.

### 1.5 Погода (безкоштовно)

- **Open-Meteo** — без ключа, без лімітів для розумного використання: вітер
  на висотах, турбулентність-проксі.
- **RainViewer API** — безкоштовні тайли радара опадів.
- **NOAA AWC** — METAR/TAF по аеропортах, `aviationweather.gov/api/data/metar`.

### 1.6 Чого свідомо НЕ буде (і це треба написати в README)

- Океанічне покриття — потрібен супутниковий ADS-B, він платний.
- MLAT для бортів без ADS-B — потрібна власна мережа приймачів.
- Розклади авіакомпаній і реальні departure/arrival gate — платні фіди.
  **Компенсація:** виводимо маршрут із бази route-lookup (`adsb.lol` має
  `/api/0/routeset` — callsign → аеропорти вильоту/прильоту, безкоштовно).
- Фото бортів — ліцензовані. Можна лінкувати на planespotters.net за
  реєстрацією, але не хостити.

## 2. Архітектура

```
                    ┌─────────────────────────────────────┐
                    │  ingest worker (Node, 1 процес)     │
                    │  - polls providers 1×/сек            │
                    │  - нормалізує, дедуплікує по hex     │
                    │  - пише в state store + history      │
                    └───────────┬─────────────────────────┘
                                │
              ┌─────────────────┼──────────────────┐
              ▼                 ▼                  ▼
      ┌──────────────┐  ┌──────────────┐  ┌────────────────┐
      │ state store  │  │ history WAL  │  │ spatial index  │
      │ Map<hex,Ac>  │  │ Parquet/SQLite│  │ flatbush/rbush │
      │ in-memory    │  │ на диску      │  │ rebuilt 1×/сек │
      └──────┬───────┘  └──────┬───────┘  └────────┬───────┘
             │                 │                   │
             └────────┬────────┴───────────────────┘
                      ▼
          ┌───────────────────────────┐
          │  API gateway (Fastify)    │
          │  - WS /stream  (viewport) │
          │  - REST /api/*            │
          └───────────┬───────────────┘
                      ▼
          ┌───────────────────────────┐
          │  Web client (Angular)     │
          │  MapLibre GL + deck.gl    │
          └───────────────────────────┘
```

**Свідоме рішення:** ніякого Redis/ClickHouse на старті. Весь поточний стан —
це `Map` у пам'яті одного Node-процесу (~25k бортів × ~200 байт = 5 МБ).
Історія — append-only файли. Це тримається на безкоштовному хостингу
і не потребує зовнішніх сервісів. Redis/Postgres додаються тільки якщо
з'явиться друга інстанція.

## 4. Протокол реального часу

### 4.1 Модель підписки

Клієнт не отримує весь світ. Він шле свій viewport, сервер шле те, що видно.

```ts
// client → server
type ClientMsg =
  | { t: 'sub'; bbox: [w: number, s: number, e: number, n: number]; zoom: number }
  | { t: 'watch'; hex: string }        // детальне стеження за одним бортом
  | { t: 'unwatch'; hex: string }
  | { t: 'filter'; f: FilterSpec }
  | { t: 'pong'; ts: number };
```

**Правило деградації по зуму** — обов'язкове, інакше на zoom 3 прилетить 25k бортів:

| zoom | що шлемо |
|---|---|
| ≥ 8 | усі борти в bbox, 1 Гц |
| 6–7 | усі борти, 2 с |
| 4–5 | топ-N за висотою + усі emergency/mil, 3 с |
| ≤ 3 | кластери (агрегація по geohash-3) + emergency, 5 с |

### 4.2 Бінарний формат апдейту

Один борт — 28 байт замість ~180 у JSON.

```
offset  size  field
0       3     icao24        uint24
3       4     lat           int32   (градуси × 1e6)
7       4     lon           int32   (градуси × 1e6)
11      2     alt           int16   (фути / 25, -1000..40000)
13      2     gs            uint16  (вузли × 10)
15      2     track         uint16  (градуси × 100)
17      2     baro_rate     int16   (ft/min / 8)
19      2     squawk        uint16  (BCD)
21      1     flags         uint8   [ground|mlat|tisb|emerg|mil|special|—|—]
22      1     category      uint8
23      1     age           uint8   (секунд від snapshot, 255 = stale)
24      4     reserved / seq
```

Фрейм:
```
0   1   type        0x01 = full snapshot, 0x02 = delta, 0x03 = removals
1   4   timestamp   uint32 unix
5   2   count       uint16
7   ..  payload
```

Callsign, реєстрація, тип ПС **не йдуть у потоці позицій** — вони статичні.
Клієнт добирає їх ліниво через `GET /api/ac/{hex}` і кешує в IndexedDB назавжди.

### 4.3 Delta-кодування

Перший фрейм після `sub` — повний snapshot. Далі — тільки борти, в яких
змінилось хоч одне поле, плюс окремий фрейм `0x03` зі списком hex, які
вийшли з viewport або зникли (`seen > 60`).

Очікуваний трафік: ~600 бортів у viewport × 28 Б × 1 Гц ≈ **17 КБ/с**,
після permessage-deflate ≈ 6 КБ/с.

## 5. Клієнт: складні місця

### 5.1 Dead reckoning — головна фішка

Дані приходять раз на 1–5 с, літак має рухатись плавно 60 fps.

```ts
// packages/geo/src/dead-reckoning.ts
interface Track {
  lat: number; lon: number;          // остання достовірна позиція
  track: number; gs: number;          // курс і швидкість
  t: number;                          // час останнього пакета
  // згладжування:
  renderLat: number; renderLon: number;
  targetLat: number; targetLon: number;
}
```

Алгоритм на кожен кадр:
1. Екстраполюй позицію: `d = gs * (now - t)`, зміщення по great-circle за `track`.
2. Коли приходить реальний пакет — **не телепортуй**. Постав його як `target`
   і зводь `render → target` за ~500 мс з `easeOutCubic`.
3. Якщо розбіжність `render` vs реальної > 5 км — це був глюк або борт
   довго не бачили: телепортуй одразу.
4. Якщо `seen_pos > 30` — почни гасити opacity іконки до 0.4; після 120 с прибирай.
5. Курс іконки теж інтерполюй по короткій дузі (враховуй перехід 359° → 1°).

### 5.2 Рендер

- `deck.gl IconLayer` з **texture atlas** силуетів літаків.
  Мінімум 12 силуетів за категорією: heavy/medium/light jet, turboprop,
  helicopter, glider, balloon, drone, military, ground vehicle.
- Колір за висотою — градієнт як у tar1090 (земля → жовтий → зелений →
  синій → фіолетовий на FL400+). Зроби це як GPU-функцію в `getColor`.
- Слідовий шлейф — `PathLayer` з fade-out, тільки для `watch`-борту
  і бортів під курсором. Ніколи не для всіх одразу.
- Цільовий бюджет: **16 мс на кадр при 5000 видимих бортах** на MacBook.
  Додай FPS-лічильник у dev-режимі і Playwright-тест, що це тримається.

### 5.3 UI-екрани

1. **Карта** (головна) — фулскрін, накладки поверх.
2. **Панель борту** — праворуч на десктопі, bottom-sheet на мобільному:
   фото-лінк, реєстрація, оператор, тип, маршрут, графік висоти/швидкості
   (uPlot), таблиця сирих полів, кнопка «слідкувати».
3. **Фільтри** — висота, швидкість, тип, авіакомпанія, країна реєстрації,
   тільки military / emergency / LADD.
4. **Сторінка аеропорту** — `/airport/LPPT`: METAR/TAF, борти в радіусі 50 нм,
   розділені на departures/arrivals за вертикальною швидкістю, роза вітрів.
5. **Сторінка борту** — `/aircraft/{reg}`: історія польотів за останні N діб.
6. **Playback** — скрабер часу, програвання історії зі швидкостями ×1/×10/×60.
7. **Статистика** — Live-дешборд: скільки бортів у повітрі, топ-оператори,
   розподіл по висотах, гістограма типів. Оновлюється раз на 10 с.

### 5.4 Доступність і дрібниці, які показують рівень

- Повна клавіатурна навігація: `/` — пошук, `f` — фільтри, `Esc` — закрити.
- URL як стан: `/?lat=38.77&lon=-9.13&z=9&sel=4951ab` — шаринг посилання
  відновлює точний вигляд.
- Темна/світла тема через `prefers-color-scheme` + ручний перемикач.
- Offline-режим: якщо WS впав — показуй останній стан приглушеним
  і банер «дані застаріли N с тому», з автореконектом (exponential backoff).
- i18n: англійська + українська, через Angular `$localize`.
- PWA: інсталюється, іконка, splash.

## 6. Історія

### 6.1 Запис

Ingest-воркер пише кожен унікальний позиційний фікс у append-only буфер,
раз на 5 хв флашить у Parquet-файл `data/history/YYYY-MM-DD/HH.parquet`
зі схемою `(ts, icao24, lat, lon, alt, gs, track, vr)`, компресія zstd.

Оцінка: ~20k бортів × 1 Гц × 16 Б ≈ 27 ГБ/добу сирих → ~2–3 ГБ/добу
після zstd + колоночного стиснення.

**Retention за замовчуванням: 72 години.** Крон-таск видаляє старіше.
Це свідомий компроміс під безкоштовний диск. Зроби retention
конфігурованим через `HISTORY_RETENTION_HOURS`.

### 6.2 Читання

`GET /api/track/{hex}?from=&to=` — читає потрібні Parquet-файли,
фільтрує по `icao24`, повертає спрощений (Ramer–Douglas–Peucker, ε = 0.0005°)
трек. Кешуй результат на 60 с.

## 8. Якість

- TypeScript `strict: true`, `noUncheckedIndexedAccess: true`, **нуль `any`**.
- Покриття тестами: `packages/*` ≥ 85 %, `apps/server` ≥ 70 %.
- Обов'язкові property-based тести (`fast-check`) для: бінарного кодека
  (round-trip), great-circle математики, dead reckoning.
- Кожен зовнішній відповідь валідується Zod. Невалідна — лог + скіп, не краш.
- Бандл: initial ≤ 250 КБ gzip. Перевіряти в CI через `size-limit`.
- Conventional Commits. Кожен PR — з описом що/чому/як перевірити.
