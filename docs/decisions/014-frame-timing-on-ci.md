# ADR-014: Бюджети кадру на CI без GPU

## Контекст

Перший прогін CI на GitHub Actions завалив `e2e/playback.spec.ts`: p95
міжкадрового інтервалу 85.9 мс проти ліміту 34 мс. Локально той самий тест
проходив.

Причина — не залізо раннера. Той самий тест на цій же машині (M1 Pro):

| рендерер                    | frames | p95 gap | worst   | long tasks |
| --------------------------- | ------ | ------- | ------- | ---------- |
| ANGLE Metal (Apple M1 Pro)  | 1026   | 17.9 мс | 22.6 мс | немає      |
| ANGLE SwiftShader (софтвер) | 232    | 79.5 мс | 469 мс  | 206 мс     |

Тобто 79.5 мс проти 17.9 мс при однаковому коді й однаковому CPU. Раннер
GitHub без GPU, Chromium падає на SwiftShader, і `requestAnimationFrame`
починає міряти презентацію софтверного растеризатора, а не роботу застосунку.

`e2e/fps.spec.ts` уже мав із цим справу: він не перевіряє fps на
SwiftShader, але й далі тримає CPU-бюджет (`frame-ms` < 16 мс при 5000
бортах) — і на CI цей бюджет зелений (1.6–1.9 мс).

## Рішення

- Детект софтверного рендерера виділено в `e2e/webgl-renderer.ts`; ним
  користуються обидва тести замість двох копій одного сніпета.
- `playback.spec.ts` на кожному хості перевіряє функціональність: година
  історії завантажилась, 1500 бортів, програвання рухає час, скраб назад
  перебудовує реєстр. Перевірки часу кадру — лише на хостах із GPU.
- CPU-бюджет на CI лишається за `fps.spec.ts`: він міряє власну метрику
  застосунку, яка від растеризатора не залежить.
- `apps/web/playwright.software-gl.config.ts` відтворює CI локально, щоб
  таку різницю було видно до пуша, а не в логах Actions.

## Наслідки

- CI не ловить регресій плавності програвання — їх ловить локальний прогін
  на GPU і `fps.spec.ts` на боці CPU. Альтернатива (підняти ліміт до ~150 мс
  для софтверного рендера) дала б зелений тест, який не перевіряє нічого:
  таке число не пов'язане ні з бюджетом із CLAUDE.md, ні з досвідом
  користувача.
- Якщо знадобиться справжня перевірка кадрів на CI — потрібен раннер із GPU,
  це вже платна інфраструктура.
- Метрика `frame-ms` не показується під час програвання (стрічку фіду
  замінює панель програвання), тому CPU-бюджет саме програвання на CI не
  перевіряється. Виносити службову метрику в DOM заради тесту не стали.
